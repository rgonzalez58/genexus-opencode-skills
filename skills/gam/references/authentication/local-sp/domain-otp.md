# GAM OTP/TOTP — Authentication Type Initialization
Initializes `GAMAuthenticationTypeOTP` by code — creates an OTP or TOTP authentication type for use as a second factor (2FA) or as a first factor (passwordless login)

Related files:
- [GAM OTP & 2FA Encyclopedia](../local-idp/domain-otp-2fa.md) — runtime flow, Backoffice configuration, enrollment, error codes
- [GAM Local — 2FA Wiring on Local Authentication Type](./domain-local.md) — wiring 2FA onto the `local` authentication type
- [GAM as SP — GAMRemoteRest (REST Password Grant) Initialization](./domain-gamremoterest.md) — wiring 2FA onto GAMRemoteRest
- [GeneXus Patterns for GAM Integration](../../debugging/common-genexus-patterns.md) — error handling patterns

Variable types:
- `&GAMAuthenticationTypeOTP` — `GAMAuthenticationTypeOTP, GeneXusSecurity` (EO)
- `&GAMErrorCollection` — `GAMError, GeneXusSecurity` — Collection: True
- `&GAMError` — `GAMError, GeneXusSecurity`
- `&Name` — `VarChar`

## Decision Points
### DP-1: Variant
- Trigger: User requests OTP or TOTP initialization
- Question: "Which variant?"
- Options:
	* `otp-2fa` (DEFAULT) — OTP via email as second factor; primary auth type must reference this by name
	* `totp-2fa` — TOTP via authenticator app as second factor
	* `otp-firstfactor` — OTP as first (and only) factor; passwordless login
	* `totp-firstfactor` — TOTP as first (and only) factor; passwordless login
- Phase: design

### DP-2: Auth type name
- Trigger: Always
- Question: "What name should this auth type have?"
- Options: free text
- DEFAULT: `otp-2fa` (DP-1 `otp-2fa`), `totp-2fa` (DP-1 `totp-2fa`), `otp-firstfactor` (DP-1 `otp-firstfactor`), `totp-firstfactor` (DP-1 `totp-firstfactor`)
- Phase: design

### DP-3: OTP code length
- Trigger: DP-1 = `otp-2fa` or `otp-firstfactor`
- Question: "How many characters should the OTP code be?"
- Options:
	* `3` (DEFAULT) — 3 numeric digits; short, low-friction
	* `6` — 6 digits; stronger
- Phase: design

### DP-4: Code expiration timeout
- Trigger: Always
- Question: "How long (in seconds) before the OTP code expires?"
- Options: numeric value in seconds
- DEFAULT: `1800` (30 minutes)
- Phase: design

### DP-5: Retry and lockout limits
- Trigger: Always
- Question: "What limits apply for failed OTP attempts? (MaximumDailyNumberCodes / NumberUnsuccessfulRetriesToLockOTP / AutomaticOTPUnlockTime)"
- Options: three numeric values
- DEFAULT: `12` daily codes / `3` failed retries before lock / `60` minutes until auto-unlock
- Phase: design

### DP-6: Impersonate (second-factor variants only)
- Trigger: DP-1 = `otp-2fa` or `totp-2fa`
- Question: "Which primary authentication type do OTP users belong to? (Impersonate)"
- Options: free text — name of the primary auth type whose user records the OTP step must resolve to
- DEFAULT: `local`
- Phase: design

## Pattern 1 — OTP second-factor (DP-1: `otp-2fa`)
Idempotent Load-or-New + Save/error shape — see [Idempotent Save Pattern](../../debugging/common-genexus-patterns.md#idempotent-save-pattern-load-or-new). Look up exact types/defaults on the `GAMAuthenticationTypeOTP` EO (EO Verification Protocol)

Top-level: `Name` (DP-2), `IsEnable`, `Description`, `Impersonate` (DP-6 — auth type that owns the user record), `UseForFirstFactorAuthentication = False`

`OTP` sub-SDT properties to set: `AutogeneratedCodeLength` (DP-3), `GenerateCodeOnlyNumbers`, `CodeExpirationTimeout` (DP-4, seconds), `MaximumDailyNumberCodes` / `NumberUnsuccessfulRetriesToLockOTP` / `AutomaticOTPUnlockTime` / `NumberUnsuccessfulRetriesToBlockUserBasedOfOTPLocks` (DP-5), `MailMessageSubject` / `MailMessageBodyHTML` (mail templates — `%1` = application name, `%2` = generated OTP code)

---

## Pattern 2 — TOTP second-factor (delta only)
Apply on top of Pattern 1: set `OTP.GenerationType = GAMOTPGenerationTypes.TOTP_Auth` (distinguishes TOTP from OTP) and `AutogeneratedCodeLength = 6` (TOTP standard). Drop `GenerateCodeOnlyNumbers` / `MailMessageSubject` / `MailMessageBodyHTML` (authenticator-app based, no mail delivery). Name convention (DP-2): `totp-2fa`

---

## Pattern 3 — OTP first-factor (passwordless)
Same Load-or-New shape and `OTP` sub-SDT properties as Pattern 1, with `UseForFirstFactorAuthentication = True` and `Impersonate = !""` (no owning auth type — this IS the first factor)

---

## Pattern 4 — TOTP first-factor (delta only)
Same delta as Pattern 2, applied on top of Pattern 3. Name convention (DP-2): `totp-firstfactor`

---

## Validation rules on Save()
`Save()` sets `Success() = False` when:
- `Name` is empty
- `OTP.AutogeneratedCodeLength` is 0

Retrieve errors: `GetErrors()` → iterate `GAMErrorCollection` — see error block in Pattern 1
