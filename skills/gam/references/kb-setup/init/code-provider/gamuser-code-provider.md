# GAMUser Code Provider
**EO**: `GAMUser` in `ref/GeneXusSecurity/` — locate by content header, not by an assumed file-name suffix (see [global-constraints.md § Where GAM's EOs live](../../../global-constraints.md#where-gams-eos-live))
Derive the SDT using the [SDT Generation Workflow](../../../global-constraints.md#sdt-generation-workflow--derive-the-sdt-11-from-the-eo)

---

## What you can use
- **Idempotency strategy**: D — void Load. `&GAMUser.Load(guid)` is void — check `&GAMUser.GUID.IsEmpty()` after. If empty: `new()`. **`GUID` and `Login` are auto-generated by GAM on `Save()`** — do not set either in the DataProvider
- **Capabilities**: load/save, password change, email change, block/unblock access, and role assignment (add/set-main/list/remove) — read the EO for exact method names and parameters
- **Read/Write properties**: derived from EO — covers name, email, authentication type name, block flags, and custom attributes. Open the EO file for the complete list
- **`AuthenticationTypeName`**: must exactly match the name of an existing GAM Authentication Type (e.g., `!"local"`)
- **`Properties` collection**: same `GAMProperty` pattern as `GAMRole` — key/value pairs for custom attributes. Open the `GAMProperty` EO for its structure

## Known facts (not derivable from the EO)
- **`GUID` and `Login` are auto-generated by GAM on `Save()`** — do not include either in the DataProvider. For idempotency when no stable GUID is pre-known, look up by email: `GAMUser.GetUsers(&filter, &errors)` with `filter.Email` set
- `Email` and `Password` should only be set during `new()` inserts. To modify an existing user: `SetPassword(newPassword, &errors)` or `ChangeEmail(newEmail, &errors)` — these are dedicated methods with their own validation/audit flow

## API quirks and order-of-operations
- **CRITICAL — Strategy D void Load**: `GAMUser.Load(guid)` is void. After calling it, check `&GAMUser.GUID.IsEmpty()` — NOT `not &GAMUser.Success()`. Using `Success()` here causes GAM error 78 (duplicate email) on the second run because the load always succeeds internally but leaves the instance empty when the user doesn't exist

## Disambiguating snippet — Strategy D check
The void Load + `GUID.IsEmpty()` check is non-obvious and error-prone. Minimum fragment to avoid the GAM78 trap:

```genexus
&GAMUser.Load(&UserDef.GUID)
If &GAMUser.GUID.IsEmpty()
	&GAMUser = new()
EndIf
```
