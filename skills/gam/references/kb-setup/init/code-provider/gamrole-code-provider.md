# GAMRole Code Provider
**EO**: `GAMRole` in `ref/GeneXusSecurity/` — locate by content header, not by an assumed file-name suffix (see [global-constraints.md § Where GAM's EOs live](../../../global-constraints.md#where-gams-eos-live))
Derive the SDT using the [SDT Generation Workflow](../../../global-constraints.md#sdt-generation-workflow--derive-the-sdt-11-from-the-eo)

---

## What you can use
- **Idempotency strategy**: A — GUID. `GAMRole.GetByGUID(guid, &errors)` (static) → if found: `Load(Id)`; else: `new()`. **`GUID` is auto-generated by GAM on `Save()`** — do not set it in the DataProvider. When no stable GUID is pre-known, look up by name instead: `GetRoles(&filter, &errors)` with `filter.Name` set
- **Capabilities**: lookup by GUID, load/save, and permission management (add/delete-all/list/delete-one) — read the EO for exact method names and parameters
- **Read/Write properties**: derived from EO — covers name, description, external ID, security policy link, and more
- **`SecurityPolicyId`**: `0` means "use repository default policy"
- **`Properties` collection**: `&GAMRole.Properties` is a `GAMProperty` collection. `GAMProperty` has `Id` (string key) and `Value` (string). Open the `GAMProperty` EO for its full structure
- **HomeObject**: stored as a `GAMProperty` entry with `Id = !"HomeObject"` and `Value = <object-name>`

## Known facts (not derivable from the EO)
- `GAMApplication.Load(1)` → GAMBackOffice (platform-constant ID). `Load(2)` → KB application. Use these to iterate all permissions of a fixed application and assign them to a role — never search by name or GUID for these two cases

## API quirks and order-of-operations
- `Properties.Clear()` MUST be called BEFORE re-adding properties on every run — stale property values accumulate across runs otherwise
- `DeleteAllPermissions()` BEFORE re-running `AddPermission()` loop — ensures idempotency; duplicate assignments accumulate otherwise
- `GAMErrors.Clear()` after each `GetByGUID` or `GetPermissions` call, before the next operation, to avoid stale error state affecting subsequent checks

## Disambiguating snippet — Assigning Backoffice permissions to a role
`GAMApplication.Load(1)` is the only reliable way to access GAMBackOffice. This pattern cannot be easily inferred from the EO alone because the numeric ID is a platform constant, not exposed as a method signature

```genexus
&GAMApplication.Load(1)
If &GAMApplication.Success()
	&GAMPermFilter.ApplicationId = 1
	&GAMPermCollection = &GAMApplication.GetPermissions(&GAMPermFilter, &GAMErrors)
	&GAMErrors.Clear()
	For &GAMAppPerm in &GAMPermCollection
		&GAMPermission = new()
		&GAMPermission.ApplicationId = 1
		&GAMPermission.GUID = &GAMAppPerm.GUID
		&GAMPermission.Name = &GAMAppPerm.Name
		&GAMPermission.Type = GAMPermissionAccessType.Allow
		&isOK = &GAMRole.AddPermission(&GAMPermission, &GAMErrors)
		If &isOK
			Commit
		Else
			// handle &GAMErrors
		EndIf
	EndFor
EndIf
```

Same pattern applies for `Load(2)` → the KB's own application
